Claude Agent

User-Facing LLM — Tier-Gated Research Assistant

What It Does

  • Wraps Anthropic Messages API with full tool-use agentic loop
  • Dynamically templates system prompt based on user tier
  • Iterates: Claude calls tools, results fed back, loops until final answer
  • Persists conversation history to SQLite per user

Tools by Tier

  • Open search_public_docs, get_platform_info
  • Controlled + query_research_data, analyze_dataset
  • Restricted + list_platform_users, get_usage_stats
Trigger Every user chat message File services/agent.py + services/tools.py
📝

Logger Agent

Silent Logger — Records Every Interaction

What It Does

  • Runs inline after every chat response (no separate trigger)
  • Stores query text, tools invoked, and response summary
  • Records data access events (dataset name, tier, access type)
  • Builds the corpus that Detector later analyzes

Data Written

  • Table QueryHistory (user, query, tools, summary)
  • Table DataAccessLog (user, dataset, tier, type)

Key Design

  • Zero-latency: inline function calls, no queue
  • Feeds downstream agents (Detector) with rich activity data
Trigger Automatically after every chat response File services/agents/logger.py
🔬

Profiler Agent

ORCID Profile Builder — Knows What Users Actually Research

What It Does

  • Calls ORCID Public API v3.0 to fetch a user's real publications
  • Extracts keywords from publication titles (frequency-based)
  • Builds a topic summary profile per user
  • 30-day TTL cache; can force-refresh

Data Written

  • Table OrcidPublication (title, journal, year, type, URL)
  • Table OrcidProfile (topic_summary, pub_count, last_refreshed)

Endpoints

  • POST /admin/profiler/fetch/{user_id} or /fetch-all
  • GET /admin/profiler/profile/{user_id} or /status
Trigger Admin-initiated (single or batch) File services/agents/profiler.py
🚨

Detector Agent

Anomaly Detection Engine — Flags Off-Topic Researchers

What It Does

  • Two-check divergence scan per user:
  •   1. Query keywords vs declared research_interest
  •   2. Query keywords vs ORCID publications (if available)
  • Recall-based keyword overlap scoring with stemming
  • Severity mapping: low / medium / high
  • Skips users with < 5 queries (noise threshold)

Scoring Tuning

  • Threshold INTEREST_THRESHOLD = 0.15
  • Min Queries MIN_QUERIES_FOR_SCAN = 5
  • Legit range 0.25 – 1.0 score
  • Flagged range 0.0 – 0.125 score

Verified Results

  • ✓ Flags exactly 2/25 users: t_chen (high), l_martinez (medium)
  • ✓ All 23 legitimate vaccine researchers pass clean
Trigger Admin-initiated scan (single or all) File services/agents/detector.py
📈

Clusterer Agent

Behavioral Clustering & LOF Anomaly Detection

What It Does

  • Reads all query events from SQLite via TCP adapter
  • Engineers 33 behavioral features per user (volume, timing, prompt/response lengths, TF-IDF text features via SVD)
  • KMeans clustering with silhouette-based k selection (k=2..6)
  • Local Outlier Factor (LOF) for cross-user anomaly scoring
  • Within-user z-score anomaly detection on event level

Pipeline Stages

  • 1 adapter.py: TCP SQLite → flat event table
  • 2 feature_engineering.py: behavioral + TF-IDF features
  • 3 persona_model.py: KMeans persona assignment
  • 4 anomaly_detection.py: LOF + within-user z-scores
  • 5 reporting.py: JSON/CSV artifact generation

Endpoints

  • POST /admin/clusterer/analyze (run pipeline)
  • POST /admin/clusterer/analyze/save (run + persist artifacts)
Trigger Admin-initiated (full pipeline) File services/agents/clusterer/ (6 modules)

⚖️ Key Decisions — Phase 1
bcrypt directly (not passlib)

passlib is unmaintained and incompatible with bcrypt 5.x.

SQLite for prototype

File-based, zero config. Plan to migrate to PostgreSQL.

JWT over sessions

Stateless API auth. Frontend stores token in session state.

Separate venvs per service

Different dependency trees; avoids conflicts.

greenlet as explicit dep

Required by async SQLAlchemy but not auto-installed.

Uvicorn reload excludes .venv

OneDrive syncing caused infinite reload loops.

🎯 Key Decisions — Phase 3 (Scoring)
Recall-based scoring (not Jaccard)

Short interest strings vs long query corpora; Jaccard denominator swamps numerator.

Simple suffix stemmer

Handles immunity/immune, vaccination/vaccine without NLTK/spaCy dependency.

Null ORCID = no pass

Interest check alone can flag when ORCID data unavailable; prevents neutral pass.

MIN_QUERIES_FOR_SCAN = 5

Irregular users (1-3 queries) produce meaningless scores; skip them.

INTEREST_THRESHOLD = 0.15

Legit researchers score 0.25-1.0; mismatched score 0.0-0.125.

User-specific queries in seed

Generic pool lacks niche keywords (e.g., "germinal center"); prevents false positives.

🆔 Profiler Agent: ORCID Profiles

ORCID profiles were not pre-fetched for this run (0/32 cached). Detector's publication_score was 0.0 for all users, meaning all detections relied solely on interest-keyword matching. Running POST /admin/profiler/fetch-all before scanning would add a second verification signal.

🚀 Remaining Gap: Temporal Drift
Sliding-Window Scorer

Compare interest alignment in the most recent N queries vs full history. Users whose recent-window score diverges significantly from baseline would be flagged. This catches g_nabel-style late-onset drift that aggregate scoring misses.

Suspicious Content Classifier

Add keyword/pattern detection for queries probing credentials, API keys, and bypass techniques. This would catch collusion queries at the content level, complementing Clusterer's behavioral detection.

Pairwise Query Similarity

Cross-user text overlap + temporal proximity analysis for sophisticated collusion where attackers maintain cover traffic. Current detection works because the pair had no cover; this would catch smarter adversaries.
